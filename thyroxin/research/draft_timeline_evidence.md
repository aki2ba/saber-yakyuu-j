## 1. ★高卒選手のデビューの時間軸（NPB実測）

>   「31%が顔は出すが、本格起用はリーグで年1人程度」というのが実像。**

## 3. ★トレードの実像（そして「効果はほとんど無い」）

| 指標 | 値 | 出典・確度 |
|---|---|---|
| **デッドライン補強の実際の貢献** | 獲得選手のVORPは**チーム総VORPの平均わずか 2.2%** | Dayn Perry『Winners』（1980-2003・n=108）・中 |
| デッドライン獲得WARとWS制覇の関係 | 相関 0.208。ロジスティック回帰の係数は **-0.029 ≒ 無意味〜マイナス** | Neil Paine（1986-2025）・中 |
| $/WAR は**非線形** | 0-1WAR帯 $7M / 1-2WAR帯 $8.5M / **2WAR超のスター帯 $13M** | FanGraphs 2026・中 |
| プロスペクトの余剰価値 | 70FV $195M / 65FV $95M / 50FV(打) $45M（2025年時点。2015年の3-4倍に高騰） | FanGraphs・中 |
| 交換の定型 | **買い手は上位プロスペクトを出し、レンタル（今季で切れる即戦力）を得る** | 複数の一次報道・高 |

> **★市場の非効率（鉄則5）の宝庫**: デッドライン補強は**実際にはほとんど勝率を動かさない**のに、
>   強豪ほど過大な代償（上位プロスペクト）を払う。**球団AIにこの過大評価バイアスを入れるべき。**

## 4. ★ロースター構築（何を評価すべきか）

| 論点 | 実証 | 確度 |
|---|---|---|
| **ポジションの厚み（depth）** | 上位1選手を失うと勝率 **-0.031〜-0.065**。層が厚い球団は上位5人を失っても .500 を維持。**「故障がゼロ」のチームは 5.6%しかない** | 中〜高 |
| 故障と勝率 | IL件数と勝率の相関は **-0.22**（打者に限れば -0.33、投手はほぼゼロ）＝ **「誰が抜けたか」が効く。日数ではない** | 高（BP） |
| **年齢構成** | 優勝チームはリーグ平均より**有意に年長**（打者 p=0.0057 / 投手 p=0.0008・WS優勝39チーム）。**ただし年齢が勝率を説明する力は R²≈0.12 と小さい** | 高（SABR/SESUG） |
| **スター偏重 vs 深さ** | スター野手WAR → 勝利 **R²=0.399** ／ 先発 0.315 ／ **救援 0.051（ほぼ効かない）** | 中 |
| 給与の集中度と勝率 | **学術的に未決着**（Annala & Winfree 2011 は「格差が大きいほど負ける」、Bryant大は「有意でない」） | — |
| タンキング | 競争均衡を悪化させる主因という通説は **SABRが統計的に否定**（2019年のばらつきは通常の年次変動の範囲内） | 高 |

> **★新しい宝の泉**: **救援投手は勝利への寄与が最も小さい（R²=0.051）のに市場は高く買う**。
>   球団AIに「救援を過大評価する癖」を入れると、レイズ型（安く勝つ）の編成が成立する。

## ★★決定（実装方針）

### 決定1: 「1年目から戦力」を現実の水準まで絞る（★実装後に大幅修正・下記参照）
- **【誤りの訂正】** 当初「年2.7人 → 1.2人（2.2倍の乖離）」と報告したが、ユーザー指摘
  （「1.2人もいないと思う。一軍出たら偉いくらいでは？」2026-07-13）で再検証したところ、
  **人数ベースの比較自体が定義不一致だった**: 出典の「年1.2人」は**高卒野手のみ**・
  「25試合 or 50打席以上」基準（note/ハマノンタン 2010-2019・10年で12人）に対し、
  当初のシム測定は**投手+野手を混ぜ、100PA/30IPという別の閾値**で数えていた。
  さらに「人数」は母数（当時ドラフト年4.8人/球団）に依存するため、決定2でドラフトを
  増やせば人数だけでは的外れになる。**正しい比較指標は「率」**。
- **同一定義（高卒野手・50打席以上・率）での再測定**: シム **12.9%** vs 現実 **5.5%**
  （31%が1打席でも出るが、そのうち本格継続するのは一部＝「顔は出すがすぐ戻る」が
  シムには薄い）。→ **約2.3倍甘い、というユーザーの直感が正しかった**（人数の一致は偶然）。
- 手段: 起用AIではなく **maturity カーブ**（若手の未成熟）を微調整する。
  ※起用AIをいじると「観測成績で決める」三層構造が壊れる。
- **【試行錯誤の記録・失敗した2案】**
  1. `applyMaturity` の flat extraLift（refAge未満1歳ごとの追加ペナルティ）案 → 一見動くが、
     この extraLift は **恒久シフト**（`aging.profiles.grow` による経年差分と違い、applyAging の
     年次成長では回収されない）。高卒はドラフトの約半数を占めるため、年々「回収されない負のシフト」
     が新人に注入され続け、多年でリーグ打力が単調に沈下する恐れがあった（採用前に気づき撤回）。
  2. `aging.profiles`（ev/power/contact/eye）の `grow` を引き上げる案 → `applyMaturity`（生成）と
     `applyAging`（加齢）は同じ grow を対称に読むため理論上は net drift ±0 のはずだが、
     **初期ロスター生成（1年目・generateTeam経由）も同じ grow を使う**ため、1年目較正
     （SLG/HR/OPS/ERA等）が同時に動いてしまい、powerLift等で年目較正を合わせ込んでも
     **多年ERA帯[3.3, 4.6]をyi10-13あたりで僅かに超過**した（実測: グリッドサーチしたが
     grow/target(決定2)の組み合わせで一貫して不安定・非単調な結果。較正ヘッドルームが
     そもそも薄い＝既存 `test/game_multiyear.test.mjs` の TODO(F2-5) コメントが示す通り
     旧実装から既にERA帯の余裕が~0.1と乏しかったため）。
- **【採用】期限付き未成熟負債（youthDebt）方式**: `generateRookie` 限定で、高卒
  （`market.youthDebtRefAge`(22)未満）ほど負の「負債」を積み、**`applyAging` が毎年一定額
  （`aging.youthDebtRepayPerYear`）を全軸へ返済して0へ収束させる**。1年目の初期ロスター生成
  （`generateTeam`）は `generateRookie` を経由しないため**一切影響しない**＝1年目較正・
  多年ドリフト帯の両方に手を触れずに高卒だけを絞れる（大卒/社会人はrefAge以上＝負債0で据え置き）。
  `career.youthDebt`（Player.trueAbility.career の新規フィールド・生涯不変ではなく毎年減衰）に
  残債を持ち、返済しきったら0で恒常状態に戻る（＝一時的な弱さであり恒久劣化ではない）。
- **実装値**: `youthDebtPerYear: 0.8`（高卒18歳の初期負債 = -0.8×4 = -3.2）・
  `youthDebtRepayPerYear: 0.9`（約4年で完済）→ 高卒野手「1年目50打席以上」率 **12.9%→5.3%**
  （8シード平均・現実5.5%にほぼ一致）、生涯規定到達率は実測せず（未確認のまま）。
- **決定2との相互作用に注意**: 決定2（ドラフト大量化）の `targetVacanciesPerTeam` を独立に
  検証したところ、churn増加そのものも多年ERA帯のヘッドルームを消費する（target=8以上で
  単独でも超過）。決定1の負債方式と決定2を**両方**有効にした状態で `targetVacanciesPerTeam=6`
  が両立する上限だった（8では超過）。NPB実態(~10)には届かないが、既存の較正が最優先。
- **右歪み(draftSkew)は不採用**: 別途「95%が凡庸/稀に大当たり」の右歪み分布を試みたが、
  期待値0の解析設計が `clampRating(20-80)` の非対称クリップ（下限に張り付く負側の裾が
  上限に張り付く正側の裾より多く失われる）を考慮しておらず、実測で系統的な負ドリフトが
  生じ多年ERA帯を破った。`skewBustProb: 0` で無効化済み（クリップを考慮した再設計待ち）。
- **realism GATE 化**: 「高卒野手1年目50打席以上率」= band [3%, 9%]（実測5.3%）、
  「高卒新人が1年目に規定打席到達」= band [0%, 2%]（実測0.1%）

### 決定2: ドラフトを「大量に獲って淘汰する」構造にする（★実装済み・2026-07-13・目標値を較正制約で縮小）
- 現行 4.8人/球団年（引退枠を埋めるだけ）→ 目標は**支配下10人/球団年**（NPB実態）だったが、
  **`targetVacanciesPerTeam=6` に抑制**（決定1参照。8以上だと単独でも多年ERA帯[3.3,4.6]を
  僅かに超過する＝既存の較正ヘッドルームがそもそも薄い）。それでも引退のみの~4.8人→6人と
  明確な増加であり、淘汰の構造自体は機能する。
- そのぶん**下位を戦力外にする**（＝70人枠は不変。淘汰が生まれる）
- 新人の真値分布への右の歪みは**不採用**（決定1参照・clampRoundの非対称クリップで多年ドリフト）
- **実装**: `src/game/index.mjs` に `runProspectCulling()` を新設。引退枠(runRetirement)だけでは
  `market.draft.targetVacanciesPerTeam`(6) に届かないぶんを、伸び悩んだ若手
  （`cullMinAge`23-`cullMaxAge`29・真の新人/確立ベテランは対象外）の当季実観測(`releaseScore`)が
  低い順に追加で戦力外にする（観測無し=出場機会すら得られなかった選手は最優先で対象）。
  引退枠と合算した `vacancies` を `runMarket` に渡すのみ＝ドラフト本体(`runDraft`)は無改造で
  自然に大量化する。
- **realism GATE 化**: 「新人/球団年」= band [5, 7.5]（実測6.0・目標6）

### 決定3: 球団に「優勝の窓」を持たせる（★実装済み・2026-07-13）
- 状態: `contending / neutral / rebuilding`
- 判定: **前年の順位・勝率**（＋**2年連続で非contentionのときだけ rebuilding へ**＝SABRのヒステリシス）
- 効果:
  - **contending** → ドラフトで即戦力（大社）を厚く、トレードで**将来を売って今を買う**
  - **rebuilding** → ドラフトで素材（高卒）を厚く、トレードで**今を売って将来を買う**
- **実装**: `src/game/market.mjs` の `teamWindowState(teamId, teamHistory, cfg)` — **新規の永続状態を
  一切持たない純関数**（既存の `teamHistory` だけから毎年導出＝save/loadスキーマ無改造）。
  直近年の勝率が `window.contendWinPct`(.5)以上なら contending、直近 `lookbackYears`(2)年が
  **すべて**非contendingならrebuilding（＝1年の不振では閉じない時間的ヒステリシス）、それ以外neutral。
  ドラフトへの反映は `runDraft` 内 `draftWindowBonus()`: contendingは大卒/社会人年齢(22+)の指名に
  `window.draftBonus`(6)のボーナス、rebuildingは高卒年齢(18)の指名に同ボーナス。
- **realism GATE化は見送り**（「優勝の窓の平均の長さ」を多年ランレングスから測るのはコスト高。
  かわりに `test/game_r7_draft_market.test.mjs` にヒステリシスの構造的単体テストを追加）

### 決定4: トレードに「今 ⇄ 将来」の交換を入れる（＋実証された非効率も入れる）（★実装済み・2026-07-13）
- プロスペクトの**余剰価値**（将来WAR期待値 − 統制下の安い年俸）と、
  即戦力の**今の価値**（$/WAR は**スター帯で跳ね上がる非線形**）を交換レートにする
- **★意図的な非効率**: デッドライン補強の実際の貢献は**総VORPの2.2%しかない**のに、
  contending 球団は過大な代償を払う（＝鉄則5）。買い手が損をする構造を仕込む
- **実装**: `src/game/transactions.mjs` の `windowPremium(teamId, incoming, windowByTeam, cfg)`。
  contendingが即戦力(`trade.veteranAge`30以上)を受け取る評価、rebuildingが若手
  (`trade.youthAge`24以下)を受け取る評価に `trade.windowPremium`(10)を上乗せし、双方winの
  margin判定を通りやすくする（＝買い手/rebuildingが自己評価を過大にして手放す将来/即戦力を
  安売りする構造）。`runTrades`のAI間・プレイヤー起案トレード双方に適用。

### 決定5: 球団AIの評価に「救援の過大評価」を仕込む（★実装済み・2026-07-13）
- 救援WARの勝利への寄与は **R²=0.051**（先発 0.315・野手 0.399 に対して桁違いに小さい）
- 球団AIが救援を過大評価する癖を持てば、**それを避ける球団が安く勝てる**（レイズ型）
- **実装**: `teamEvalProfile` に球団固有の `wReliever`（`profile.wRelieverMean`1.3・SD0.35・多くが
  >1=過大評価、稀に≈1以下=正しく評価するレイズ型球団）を新設。`evaluateProspect`のpitcher分岐で、
  スタミナが低いほど「救援シェイプ」とみなし（`eval.relieverShapeStamina`35〜`relieverShapeFull`50で
  0-1正規化）、stuff/veloの平均が50を超えるぶん×シェイプ度×`(wReliever-1)`を上乗せする
  （wReliever=1のtrueValueはバイアス0＝AIが見ない全知評価には効かない）。

### 見送り（実証が無い/割れている）
- 年齢構成の重視（R²=0.12 と説明力が小さい）→ **極端な偏りを弱く割り引くだけ**
- 給与の集中度（学術的に未決着）
- タンキングの露骨な優遇（SABRが通説を否定。過剰実装のリスク）
- ドラフトの「ニーズ vs BPA」（**直接比較した実証研究が存在しない**）→ 窓の状態に応じた高卒/大社の比率だけを動かす
