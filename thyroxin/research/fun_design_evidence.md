# 「ゲームとしての面白さ」の設計 — 実在ゲームの実例調査と設計提案（2026-07-14）

> 三原則③「やきゅつく的な楽しさ」の本格追求。やきゅつく／パワプロ（栄冠ナイン・ペナント）／
> OOTP・海外経営シムの3系統をWeb調査し、「面白さの仕組み」を横断分析した上で、
> 本プロジェクトのアーキテクチャ（三層構造・決定論・config集約）に適合する設計を提案する。
> 出典は各節に記載。実装仕様化の際は本書を正典として `thyroxin/specs/` に落とすこと。

## 1. 調査サマリ（ゲーム別の「面白さの仕組み」）

### 1.1 やきゅつく（プロ野球チームをつくろう）シリーズ

| 仕組み | 動作 | なぜ面白いか |
|---|---|---|
| **ドラフト指名** | オフに新人を指名・交渉 | **シリーズ最大の楽しさと攻略wikiで言及**。不確実性下の選択が最高の心理的ペイオフ。ポジション・予算・適性の複数変数の同時判断 |
| 経営の閉ループ | 施設投資→選手成長→成績→ファン数→収入→再投資 | 投資効果が数年後に現れる遅延が計画性を要求。毎月の収支管理が緊張感を生む |
| キャンプ地・練習相性 | 前年成績で選べるキャンプ地が変わる。練習メニュー×アイテムに相性◎○ | 反復プレイでの最適化発見。「完全な最適解がない」ことが繰り返しを誘う |
| 育成の完全制御感 | 試合は間接的だが、上流（経営・育成・獲得）は全部自分で決める | 「自分の理想のチームを作れる」= シリーズ最大の魅力とレビューで繰り返し言及 |
| 30年スケール | 選手の入団→成長→衰え→引退を見届ける | 人生に匹敵するタイムスケールが「やめられない」粘着性を生む |

主な出典: silentbeatle.com（経営メニュー解説）, wiki.yakyutsuku.game-syo.com, remake-game.jp, gamezukushi.com

**教訓（失敗例）**: PS2版3はスキルシステムで深度を増したが「枠が少ないのに耐久度だけ上がり
選手の入れ替えが困難」「年俸高騰」で不評 → **システムの深化が運用の煩雑さに変わる境界がある**。

### 1.2 パワプロ（栄冠ナイン・ペナント）

| 仕組み | 動作 | なぜ面白いか |
|---|---|---|
| **終わりのないループ** | 甲子園で負けても翌年新入生が来て物語が再開。クリアもゲームオーバーもない | 敗北が「失敗」でなく「次世代の物語の始まり」に変換される。負けた直後こそ続けたくなる |
| **間接操作＋運** | 選手は直接操作できず指示のみ。成長も試合も乱数次第 | 「指示してお祈り」のギャンブル的快感。新入生ガチャがローグライク的リプレイ性を生む |
| **卒業＝設計された喪失** | 3年で必ず別れる。エースも補欠も等しく卒業 | 有限性が愛着を最大化する。「一期一会」の哀愁と新世代への希望の共存 |
| **特殊能力（金特/青特/赤特）** | 数値と別に「勝負強い」「ムラっ気」等の離散ラベル。状況発動 | 連続数値では表現できない**個性の言語化**。一目でキャラが読める。赤特（欠点）が選手を人間らしくする |
| 物語の自己生成 | ゲームは乱数を提示するだけ。プレイヤーが名前を付け、ドラマを脳内補完 | 自作の物語なので愛着が最大化。失敗は「監督の私が未熟」と自己帰属→再挑戦動機 |
| 敵チームの成長・再会 | 敵校も成長し、後年に成長した姿で再会する | 負けた相手も生き続けている世界観が、敗北を「別の物語」に昇華（開発者が「栄冠らしさ」として堅持） |
| 性格システム | 性格（やんちゃ/熱血漢/クール/内気/天才肌等）で成長しやすい能力・イベント・伝令効果が変わる | 数値が同じでも「別人」として認識され、個体への愛着を生む |
| **信頼度→采配の手応え** | 出場・食事会で信頼度上昇。試合中の戦術成功率が「能力×信頼度×調子＋乱数」 | 「信頼している選手ほど采配に応えてくれる」関係性が、数値でなく挙動として体感される |
| 覚醒イベント | 低能力選手が突然大幅成長 | 開発者曰く「高校生年代は何かをきっかけにいきなりうまくなる」現実の再現。**ハズレ選手にも期待を残す** |
| OB効果 | 卒業生は進路（プロ/大学等）を持ち、OBとして母校に効果をもたらす | 別れが完全な喪失にならず、関係が「変化」として続く |

主な出典: Number PREMIER（栄冠ナイン分析）, note.com/sweet19, ファミ通インタビュー
（パワプロ2022堀井氏・2024 30周年松井P・栄冠クロス開発）, Game8, 路傍のちゃばしら, Real Sound

**教訓（ダレるポイント＝やってはいけないこと）**:
1. **易化はカタルシスを壊す**: 2026版は初挑戦で2年目から甲子園3連覇できるほど易化し
   「弱小校から成り上がる体験が崩れた」と批判 → **適度な敗北こそがループの動機**
2. **最適解の画一化**: 「走力ミート＋転がせ」が歴代最強で育成・采配が単調化
   → 支配戦略が1つに収束するとリプレイ性が死ぬ（本プロジェクトは球団評価関数の多様性=
   市場の非効率が既に対策になっている。育成方針にも同じ設計が要る）
3. **苦痛時間の強制**: 負け試合のスキップ不可への不満 → 時短手段は常に用意する
   （本プロジェクトは advanceTo 進行が既にあるので方向性は正しい）

### 1.3 OOTP（Out of the Park Baseball）・海外経営シム

| 仕組み | 動作 | なぜ面白いか |
|---|---|---|
| **オーナー目標** | 優先度付きの目標（動員改善・特定補強・黒字維持等）。**交渉で別の目標に差し替え可能**。失敗が積もると解任 | 目標の外部化がプレイに方向を与える。交渉可能性が「理不尽さ」を緩和 |
| **ニュース自動生成** | イベント駆動（完封・記録・トレード・契約噂）でテンプレート記事が湧く。公開/個人の2層＋購読フィルタ | シミュレーションの深さを「読める物語」に変換。個人メッセージ（オーナーからの評価等）が当事者感を作る |
| **選手人気と経済の連鎖** | 人気（全国/地元の2値）=成績主体＋イベント修正値（減衰付き）。人気選手の放出→ファン関心低下→収益減 | 「強さ」と別軸の価値（人気）が編成判断に葛藤を持ち込む |
| ユーザー作成リキャップ | 試合の見出し・記事を自分で書ける | dynasty report文化（セーブデータの物語化）の土台。プレイヤーが物語の作者になる |
| 難易度の設計 | Baseball Mogul: 難度を上げると予算縮小+AI強化。FoF: 成績/財務/ロスター価値/フランチャイズ価値の4領域総合評価 | 目標でなく「制約」で難しさを作る設計もある |

主な出典: OOTP公式Wiki/マニュアル（Ownership, Manager News, Player Popularity, Personalities）,
OOTPフォーラム検証スレッド, Baseball Replay Journal, Wikipedia

**教訓（失敗例）**: OOTPのオーナー目標は「再建期に補強を要求」等の**矛盾した目標**が出ることが
コミュニティの不満 → **目標生成には文脈（チーム状態）との整合性チェックが必須**。
幸い本プロジェクトには `teamWindowState`（contending/neutral/rebuilding）が既にあるので接続できる。

## 2. 横断分析 — 面白さの核となる8つの心理メカニズム

3系統に共通して現れたパターン。設計はこれらを満たす形で行う。

1. **不確実性下の選択**（ドラフト・ガチャ・スカウト評価の霧）— 最高のペイオフはここから出る
2. **制御感**（上流=経営/育成/獲得は全部自分。下流=試合結果は間接）— 「自分の理想のチーム」
3. **有限性と喪失**（卒業・引退・契約切れ）— 愛着は別れの予感から最大化する
4. **物語の自己生成**（ゲームは乱数と素材だけ提示。解釈はプレイヤー）— 与えられた物語より強い
5. **個性の言語化**（数値でなく離散ラベル。欠点も含めて）— 愛着の取っ掛かり
6. **目標の外部化**（オーナー・ファン・メディアからの要求）— 自由すぎる砂場に方向を与える
7. **経済の閉ループ**（成績→ファン→収入→投資→成績）— 意思決定に重みとトレードオフを与える
8. **失敗の許容**（負けても次の物語が始まる。解任されても別球団で再起）— 再挑戦の中毒性

**本プロジェクト固有の強み**: 三層構造（真値/観測/球団評価）は上記1・4の源泉として既に機能する
設計になっている（req_1 §12「三層のズレこそドラマ全部の源泉」）。市場の非効率（鉄則5）も同様。
つまり**土台は既にある。足りないのは「プレイヤーがそれに触れる手段」と「意思決定の重み」**。

## 3. 現状の棚卸し（プレイヤーができること／できないこと）

### できる（実装済み）
- チーム選択・日次/週/月/シーズン進行・複数年キャリア
- 采配介入（監督方針: 犠打/盗塁/敬遠/継投傾向等）
- 観戦モード（1球/1打席/1イニング/自動再生）
- ストーブリーグ: FA入札・トレード起案/AIからの提案受諾
- 閲覧: 全セイバー指標・順位・日程・ニュース（試合ノーテーブル・週間ダイジェスト）・
  記録（球団史/リーグ記録/二つ名/マイルストーン/表彰）

### できない（未実装＝面白さのギャップ）
- **ドラフトに参加できない**（完全AI自動）← やきゅつく調査で「最大の楽しさ」とされた部分が丸ごと無い
- **育成に触れない**（成長は完全自動。キャンプ・練習方針・コンバート指示が無い）
- **経営資源が無い**（資金・年俸・ファン・予算制約が無い＝FA入札もトレードもノーコスト）
- **目標が無い**（オーナー・ファンからの要求が無い＝何のために勝つのかはプレイヤー任せ）
- **選手の個性が薄い**（能力値と成績はあるが、性格・人となり・欠点のラベルが無い）
- **物語の追跡が単発**（ニュースは1試合単位。新人王レース・記録ペース・引退ロード等の連続線が無い）

## 4. 設計提案 — 5つの柱（優先度順）

### 柱1: プレイヤー参加型ドラフト会議 【最優先・中コスト】
> 根拠: やきゅつく調査の最重要発見「ドラフトが最大の心理的ペイオフ」。現状は結果を眺めるだけ。

- オフシーズン進行を「ドラフト会議」画面で一時停止し、**自チームの指名だけ人間が選ぶ**
  （他11球団はAIが従来通り指名。1位競合くじのドキドキはエンジンに実装済み＝そのまま活きる）
- プレイヤーに見せるのは**スカウトレポート**（真値ではない）: 球団のスカウト網による
  評価等級＋伸びしろ見立て＋世代内順位＋「隠し玉」フラグ。三層構造そのまま
  （evaluateProspect の自球団評価を人間可読にするだけ）
- 実装: `marketInterventions` に `phase:'draft'` 介入（指名候補の優先リスト）を積み、
  `runDraft` が自チームの番で介入リストを参照する。**決定論・save/load再現は既存の介入ログ
  パターンに完全に乗る**（bidFA/proposeTradeと同型）
- ドラフト候補の「注目選手」事前報道（ニュース連携: 「今年の目玉は高卒左腕○○」）で
  会議前から物語を始める

### 柱2: 育成方針・キャンプ（間接介入＋お祈り） 【高価値・中コスト】
> 根拠: やきゅつく（キャンプ・相性）＋栄冠ナイン（間接操作＋運こそエモさ）。

- **直接能力を上げさせない**（三層構造と較正の保護）。介入は「方針」レベル:
  - 選手ごとに育成方針タグ: 打撃強化/守備強化/コンバート挑戦/休養優先/現状維持
  - 春季キャンプで年1回、注力選手を数人指名（「特別指導枠」）
- エンジン側: 方針は `applyAging`/`applyBreakouts` の**分布の形だけを傾ける**
  （例: 打撃強化=打撃軸の成長分散を+X%・守備軸を-X%で**期待値総和は保存**。
  コンバート挑戦=positionProfの習熟先を指定ポジへ振り替え）
  → 期待値保存なら多年ドリフト・較正を壊さない（R7の教訓: 恒久シフトは入れない）
- 結果は乱数次第のまま＝「指示してお祈り」。育った/育たなかったがニュースで返る
  （「特別指導の成果、○○が開眼」/「伸び悩む○○、コーチ陣も頭を抱える」）
- 将来拡張: コーチ人事（打撃/投手/守備コーチの質が方針の効きに乗る）

### 柱3: 球団経営レイヤー（予算→オーナー目標→ファン） 【背骨・高コスト・段階導入】
> 根拠: やきゅつく経営ループ＋OOTPオーナー目標＋人気→収益連鎖。意思決定に「重み」を与える。

**段階A: 年俸予算**（これだけでも効く）
- 既存の契約更改（現状フレーバー）を実弾化: チーム年俸総額に上限（球団ごとの財力差）
- FA入札・トレード・契約更改が予算を消費 → 「獲りたいが枠がない」の葛藤が生まれる
  （req_1 §12.2「枠の有限性がドラマ」= 人的補償の福地型と同じ原理を金銭でも）

**段階B: オーナー目標**
- 年頭にオーナーから優先度付き目標（例: 「Aクラス入り」「観客動員+10%」「若手野手を出場させろ」）
- **`teamWindowState` と整合性チェック**（rebuilding期に優勝を要求しない）← OOTPの失敗から学ぶ
- 達成/失敗はオーナー信任に積み上がり、信任喪失で解任（→別球団からのオファーで再起=失敗の許容）

**段階C: ファン・収入**
- ファン関心度 = 成績追随（緩やか）＋イベント修正値（優勝・スター獲得・人気選手放出、減衰付き）
  ← OOTPの実装パターンをそのまま採用
- 収入 = 動員（ファン関心×成績）＋放映権等 → 翌年の予算へ。人気選手の放出はファン関心を下げる
  （「強さ」と別軸の価値が編成判断に葛藤を持ち込む）

**この経営レイヤーは 2年目以降のオフシーズン限定で作動**（鉄則7: 1年目シム不変。
較正53指標に非干渉。エンジンの試合シムには一切触れない）

### 柱4: 選手の個性 — 性格タグ＋「観測ラベル」としての評判 【低〜中コスト・独自性が出る】
> 根拠: パワプロ特殊能力=個性の言語化（赤特が人間らしさを作る）。

- **入団時の性格タグ**（練習熱心/ムラっ気/お調子者/寡黙/闘志…）: 生成時に決定論で付与。
  効果は薄く広く（育成方針の効き・ブレイク確率・不振時の続落率に小さな補正）。
  主目的は**キャラ付け＝愛着の取っ掛かり**（ニュース・コメント文体にも反映）
- **セイバー的にユニークな設計＝「評判は観測から湧く」**: 「勝負強い」「ここ一番に弱い」等の
  ラベルを真値に持たせない（Clutchが真の能力でないのはセイバーの実証的立場）。
  代わりに**観測成績（RISP/Clutch/WPA）からメディアが勝手にラベルを貼る**
  → 「ファンとメディアが作る物語」と「真値」のズレそのものがコンテンツになる
  （既存の二つ名システム(通算観測ベース)の拡張として実装できる。三層構造の思想と完全に一致）
- 赤特相当も観測から: 「ガラスの肩」（故障歴）「ブレーキ」（併殺率）等。欠点ラベルが人間味を作る

### 柱5: ストーリーライン（連続ニュース・ライバル・引退ロード） 【低コスト・即効性】
> 根拠: OOTPイベント駆動ニュース＋栄冠「敵も成長し再会する」＋卒業=設計された喪失。

- 既存 news.mjs を「単発」から「連続線」へ拡張:
  - **レース追跡**: 新人王レース・タイトル争い・三冠王/シーズン記録ペース・200安打ペース
  - **ライバル関係**: 同期入団・ドラフト同順位・トレード相手との再会・同ポジ争い
    （「あの時放出した○○が古巣に牙をむく」= トレード/戦力外の後日談が自動で湧く）
  - **引退ロード**: 功労者の最終年演出（引退表明→引退試合→セレモニー→球団史へ）
    有限性と喪失の演出。二つ名・記録と接続
  - **個人メッセージ**: オーナーからの手紙・選手からの出場機会要望（柱3Bと接続）
- エンジン非干渉（集計値からの表示層）なので**較正リスクゼロで最初に効果が見える**

## 5. 実装順序の提案

| 順 | 内容 | 理由 |
|---|---|---|
| 1 | 柱5（ストーリーライン） | エンジン非干渉・低リスク・即効。愛着形成の土台を先に |
| 2 | 柱1（ドラフト参加） | 「最大の楽しさ」の解放。介入ログ基盤が既にあり設計が素直 |
| 3 | 柱4（性格・観測ラベル） | 柱5の物語に「人」を与える。低コスト |
| 4 | 柱2（育成方針・キャンプ） | 較正保護（期待値保存）の設計検証が必要なので慎重に |
| 5 | 柱3（経営レイヤー） | 背骨だが最大工数。A(予算)→B(オーナー目標)→C(ファン経済)の順で段階導入 |

## 6. 守るべき制約（鉄則との整合）

- 全介入は `interventions`/`marketInterventions` ログ経由（決定論・save/load再現）
- 育成介入は**期待値保存**（分布の形だけ傾ける）— R7の教訓: 恒久シフトは多年ドリフトを生む
- 経営レイヤーは2年目以降のオフ限定（1年目シム不変・較正53指標に非干渉）
- 評判・ラベルは**観測から湧かせる**（真値に「勝負強さ」を持たせない=三層構造の堅持）
- 変更後は npm test → calibrate → realism の恒常ゲート

## 7. 補足調査メモ

### パワプロ・ペナントの「三軸戦略」（柱2の直接の先行例）
KONAMI公式のペナントモードは **育成方針（投手/野手で段階別に設定）× 二軍運用（成績ベースの
入れ替え＋コーチの育成ランクが成長速度に影響）× FA市場（引き止めvs新規獲得）** の三軸で
オフの意思決定を回している。「今年の勝利」と「将来への投資」のジレンマが毎オフ発生し、
実在選手が全員引退して架空選手だけになっても経営ゲームとして回り続ける、と公式が明言。
→ 本プロジェクトの柱2（育成方針）＋柱3（予算）の組み合わせはこの構造の再現になる。
出典: konami.com/pawa/2024-2025/mode/pennant, spicapadpwpr.blog.jp

### 栄冠ナインの信頼度の内部構造（柱2の采配接続の参考）
戦術カードの成功率 =「能力 × 信頼度 × 調子 ＋ 乱数」。信頼度が高いと能力以上の数字が出やすい。
→ 「起用し続けた選手が応えてくれる」を数値でなく挙動で体感させる設計。
本プロジェクトで真値を動かすのは三層構造violation になるが、**采配介入の成功率提示**
（監督の指示の通りやすさ）のような表示層での応用は可能。
出典: game8.jp/eikan-nine/554840, saiseikojo.com
