# 実装 vs 現実の野球 リアリズム監査（2026-07-11）

## 発端

ユーザー報告:「センターの定位置に飛んだライナーがツーベースになったのに、センターのUZRが-0.0だった」。

**根本原因（確定・再現済み）**: UZRは嘘をついていない。嘘をついているのは塁打決定。
- 観戦UIの「UZR概算 -0.0」= `oaaDelta = 0 − expOut` の表示。エンジンはその打球を「捕球不能（expOut≈0）」と正しく判定していた（低いライナー、例 EV165・LA10° は CF定位置の15m手前 82.5m に落ち、滞空1.6秒では現実でも捕れない）。
- 問題は `src/sim/battedBallResult.mjs:63-77` の `decideBases`。**空中打球は「落下距離 ≥ gapDistM(76m)」だけで無条件に二塁打**になり、守備隊形を一切見ない。現実は外野手の目の前のワンバウンド＝単打。
- 定量化: 空中打球の二塁打のうち **6.0%が最寄り外野手から14m以内**（0.3%は8m以内＝ほぼ真上）に落ちた打球（30万打球シム、scratchpadで再現）。

この報告を受け、全域を10ドメインで監査（多エージェント探索 79所見 → 全件を実コード照合で検証。確定74 / 部分4 / 棄却1）。

## 検証方法

- 探索: ドメイン別エージェント（打球結果/走塁/一球機械/試合進行/采配/起用登録/指標定義/日程PS/市場/加齢故障）
- 検証: 所見ごとに該当コードを実際に読み、①実装の挙動の主張が正しいか ②現実（2020年代NPB）側の主張が正しいか を確認。config実値・生成分布・プロジェクト自身の正典（sabermetrics_glossary.md 等）とも突き合わせ。
- 現実準拠の基準: 2020年代NPB。MLB固有ルール（3打者ルール等）は要求しない。

凡例: **[S]**=毎試合観戦で見える・得点構造を歪める / **[A]**=頻繁に気づく・分布を歪める / **[B]**=制度・指標の細部。

## 1. 走塁・進塁（最重症クラスタ）

### [S] ゴロアウトで走者が一切進塁しない `src/sim/game.mjs:89`
`advanceRunners` の 'out' 分岐は空中アウトの犠飛処理のみで、ゴロアウトは「走者そのまま」（コメント自身が未実装と明記）。進塁打・「ショートゴロの間に1点」・満塁ゴロの本塁封殺・併殺崩れの間の得点がすべて存在しない。0死満塁の併殺でも三塁走者の得点=0。NPB最頻出の得点手段が丸ごと欠落し、犠打で三塁へ送った走者がゴロでは永遠に還れない＝スモールボールが構造的に不成立。

### [S] 空中アウトで三塁走者が深さ無関係に100%生還（内野フライでも犠飛） `src/sim/game.mjs:72`
`isAirOut && outs<2 && b3 → runs++` 無条件。飛距離・外野手の肩・走者の足を見ず、本塁憤死も存在しない。キャッチャーフライでも三塁走者が生還し公式犠飛（`game.mjs:720-723` で ab--/sf++）。二塁走者のタッグアップ（tagBase=0.14）も深さ非依存。現実の犠飛は「十分深い外野フライ」限定で、浅い飛球はGO/NO GO判断＋補殺リスクがある。

### [S] 失策時の進塁がフォース進塁のみ `src/sim/game.mjs:52`
失策(E)は BB/HBP と同じ押し出しロジック。外野が落球しても塁が詰まっていない走者は1個も進めない（二三塁で落球→満塁になるだけで0点）。現実は落球なら全員1個以上、三塁走者はほぼ生還。

### [A] 追加進塁の判断がアウトカウント非依存＋2死では走塁死が構造的に発生不能 `src/sim/game.mjs:167-203`
`resolveAdv` は走者能力と外野の肩のみ参照し、アウトカウントを見ない（現実は2死で打球と同時にスタート＝進塁率が跳ね上がる）。さらに `canKill = outs+outsAdded < 2` のため **2死では補殺が絶対に起きない**（現実は2死の本塁突入死が定番）。
- 併せて `singleScore1to3: 0.10`（config自身が「文献の実測値~25-40%帯」と注記しつつ1/3以下の値）`src/config.mjs:711`

### [A] 盗塁が一塁→二塁のみ `src/sim/game.mjs:214`
`attemptSteal` は「走者一塁×二塁空き」限定。三盗・本盗・重盗・ディレード・けん制（けん制死・悪送球）が存在しない。

### [A] 打席中の暴投/捕逸の得点で、無関係の外野フライが犠飛として記録される `src/sim/game.mjs:716,720`
`runs = advRuns + wpRuns` を犠飛判定（`isAirOut && runs>0`）に使うため、打席中の暴投で三塁走者が還った後に打者が外野フライに倒れると SF が付く（公式記録では暴投得点は犠飛ではない）。

### [A] スクイズが存在しない `src/sim/manager.mjs:85`
`buntAttemptProb` は「三塁走者あり」で問答無用に0。一・三塁の送りバントも消える。セ・リーグ近似を謳う上で目立つ欠落。

### [A] 犠打の解決が選手能力に非依存＋二塁単独走者で「先頭走者封殺」 `src/sim/game.mjs:1020-1075`
バント結果は固定確率表（successProb/failProb）。打者のバント技術・打者の足・投手/守備の巧拙・スリーバント失敗（三振）が存在しない。さらに失敗分岐は走者二塁のみでも `bases[1]=null`＝フォースが存在しない塁で「封殺」が起きる。

## 2. 打球結果・守備幾何

### [S] 塁打決定が守備隊形の幾何を無視（発端の穴） `src/sim/battedBallResult.mjs:63-77`
空中打球: 距離<76m→単打 / ≥76m→二塁打（±18°超×94m以上のみ三塁打抽選）。外野手の位置と無関係のため「野手の目の前のポトリが必ず2B」「真正面の深い打球でも2B」。ゴロ: `|spray|>38° × 20%固定` のみで二塁打、**ゴロ三塁打は絶対に出ない**、打球速度・打者の足も不参照（三塁線を破る痛烈な打球の80%が単打止まり）。

### [A] フェンスを越えて落ちる打球がHRにならない帯がある `src/sim/battedBallResult.mjs:120-136`
HR判定は `hrDist × hrScale(0.9695) ≥ fence`。hrLaPeak=26/conc=24/hrEvGain=0（`config.mjs:680-684`）のため hrDist は幾何の distanceM と同一値＝実質「distanceM ≥ fence×1.0315」。落下点が [fence, fence×1.0315)（中堅122mなら122〜125.8m）の打球は「フェンスの向こうに落ちる」のにインプレー（二塁打 or 捕球）。さらに **LA<15°はHR判定自体を受けない**ため、ライン際低弾道の柵越えライナーが構造的にHRにならない。観戦実況は distanceM を表示するため「飛距離124m・中堅122mでセンターフライ」が可視化される。

### [A] 捕手・投手が守備網に存在しない `src/sim/fieldingGeometry.mjs:29-31`
FIELD_POS は内野4+外野3のみ。本塁至近の真上のポップ（LA>60°は幾何モデルで落下点が極端に浅くなる）は最寄りが三塁手(34m)となり pOut≈0.90-0.94 → **キャッチャー前ポトリの単打が数試合に1回規模で発生**。現実のPU被打率は1-2%。

### [A] EVが対称正規分布で弱接触の左裾が無く、内野安打がほぼ湧かない `src/sim/battedBall.mjs:56`
`evKmh = max(40, normal(≈140, 14))`。EV<113km/h が約3%しか出ない（実分布は詰まり/先端で60-110km/hが1-2割）。ゴロ送球モデル（runnerToFirstS=4.35 vs 平均ゴロの送球完了~3秒）では pThrow≈1 に張り付き、「足で稼ぐ内野安打」がほぼゼロ。俊足スラップ型（内野安打で打率を作る選手像）が生成不能で、`runnerToFirstPerRating` ノブが事実上死んでいる。

### [B] ファウルテリトリーが存在しない `src/sim/battedBall.mjs:67-69`
sprayは±50°クランプでファウルライン(±45°)外の打球もフェア処理（全打球の1%強）。スプレーチャートにライン外の安打が恒常的にプロットされる。捕邪飛（ファウルフライアウト）も存在しない（ファウルは常にストライク加算のみ `plateAppearance.mjs:247-253`）。

## 3. 試合進行・記録規則

### [S] 継承走者の失点が全て「その時の投手」に付く `src/sim/game.mjs:470,758-759`
失点計上は打席時点の投手（pStat）へ一括。満塁で登板した救援が単打を打たれると3失点とも救援に付く。公式規則（走者は出した投手の責任）と真逆で、火消し役のERAが系統的に過大・先発のERAが過小になる。リリーフの防御率分布が現実と合わない構造要因。

### [A] 捕逸(PB)で入った得点が自責点になる `src/sim/game.mjs:714-716,759` / `plateAppearance.mjs:296-307`
暴投と捕逸を wpRuns に合算し `er += runs`。公式では捕逸による得点は非自責（暴投は自責）。

### [A] 失策後の同イニング得点が一律非自責（イニング再構成なし） `src/sim/game.mjs:429,759`
`errorInInning` フラグ一発で以降全て非自責。公式は「失策がなくても得点したか」を再構成する（2死からの失策後でも、後続のソロHR打者自身の得点は自責）。自責点が系統的に過小。

### [A] サヨナラ時に決勝点以降の得点も全て加算 `src/sim/game.mjs:840`
サヨナラ判定は打席プレー完了後。安打によるサヨナラでも打席の全得点が入る（公式は本塁打以外は決勝点まで）。「9回裏サヨナラで2点差勝ち」というスコアが出る。

### [A] セーブ/ホールドの成立条件が公式規則と乖離 `src/sim/game.mjs:1260-1282`
セーブ = 「最後に投げた・勝利投手でない・**最終**点差≤3・**1アウト以上**」。公式は登板時点の状況（3点差以内で1イニング以上 / 同点の走者・打者 / 3イニング）で判定。5点差で登板→2失点でも最終3点差ならセーブが付く等。ホールドも enterInning≥7 固定条件が公式に無い。

### [B] 振り逃げ（第三ストライク不捕球）・ボーク・打撃妨害が存在しない `src/sim/plateAppearance.mjs`
振り逃げ: K は常に即アウト。ボーク・打妨は概念ごと不在（低頻度事象のため low）。

### [B] 申告敬遠制度と矛盾（敬遠1回=投球数4加算） `src/sim/game.mjs:578-584` / `config.mjs:362`
NPBは2018年から申告敬遠（0球）。lumpedPitches で率の分母からは除外済みだが、球数表示は膨らむ。

## 4. 一球機械（カウント状態機械）

### [A] 球速(velocityKmh)が一球シミュレーションの結果に一切影響しない `src/sim/plateAppearance.mjs:170-235` / `src/generate.mjs:74-90`
現行の一球機械は球種の whiff 値のみ参照。球種 whiff は生成時に球速と**独立に**抽選される（`draw(rng,50,15)`）。velocityKmh を使う `paProbabilities` は legacy（config自身が「現行シム不使用」と注記）。つまり158km/h の本格派が三振を取れる保証がどこにもなく、球速は加齢の declineRate/peakAge と表示にしか効かない。選手カードの球速表示と成績が乖離しうる。

### [A] 2ストライク時にゾーン内空振りがほぼ消滅 `src/sim/plateAppearance.mjs:234-235` / `config.mjs:282,291`
whiffZoneBase=0.175 − whiffTwoStrikeW=0.235 → 平均的な組み合わせで clamp 下限 0.01 に張り付く。「2ストライクからゾーン内の球で空振り三振」がほぼ発生せず、三振の内訳が見逃し/ボール球スイングに偏る。

### [B] 球数・スタミナによる球威低下が存在しない
一球機械内に疲労項が無い（TTO=巡目のみ）。スタミナは降板判断（starterPitchLimit）にしか効かず、「100球超で球威が落ちて捕まる」現象が出ない。

## 5. 采配AI

### [A] クローザーがセーブ機会(リード1-3×9回以降)以外に絶対登板しない `src/sim/manager.mjs:283-314`
同点の9回裏・延長でも closer は温存され（プールから常に除外・最後は「現投手続投」）、現実の「同点9回にクローザー投入」が存在しない。

### [A] 野手への代打が「同点以下×得点圏」限定 `src/sim/manager.mjs:133-137`
9回1点差ビハインドの先頭打者（走者なし）に代打が出ない。現実の終盤代打の定番場面が欠落。

### [A] 投手への代打判断が球数・投球内容を一切見ない `src/sim/manager.mjs:128-132`
5回以降×(ビハインド or 同点得点圏)で、完封中のエースでも即代打。「好投中だから続投」という判断軸が無い。

### [A] 9回続投=完封継続中のみ → 1〜3失点完投がほぼ存在しない `src/sim/game.mjs:1119-1124`
`stay = runs===0 && …`。現実のNPB完投の過半は失点あり完投。完投≒完封に縮退。

### [B] イニング途中の継投が「既に打たれた後」にしか発動しない `src/sim/game.mjs:1153-1173`
交代条件は球数/失点閾値のみ。無失点でも走者を溜めたピンチでの事前交代（火消し）が無い（chooseReliever のレバレッジ駆動は「交代が決まった後」の人選のみ）。

### [B] 救援選択に打者の左右・マッチアップ概念が無い `src/sim/manager.mjs:268-330`
NPBは3打者ルール未導入でワンポイント左腕が現存するが、シムには存在しない。

## 8. ストーブリーグ・表彰

### [A] FA人的補償の選択権が事実上「移籍先」にある `src/game/transactions.mjs:179-186`
コメントは「流出元が自評価で最良の1人を獲る」と書くが、コードは **winner（移籍先）の評価で最低の選手** を差し出す（コメントとコードが矛盾）。現実は流出元がプロテクト外から自由に選ぶ（内海・長野型の事件性が出ない）。またランク制（A/B/C）・金銭補償が無く、**同型の非プロテクト選手を用意できないとFA移籍自体が消滅する**（`pool.length==0 → continue`）。

### [B] ドラフト2巡目以降が毎巡同じウェーバー順 `src/game/market.mjs:269-276`
NPBは2巡目ウェーバー→3巡目逆ウェーバーの折り返し（スネーク）。

### [B] 新人王資格が「過去に1試合でも出場したら永久喪失」 `src/game/awards.mjs:123-152`
`isRookie = 過去seasonの成績が1行でもあれば false`。NPBは累計60打席以内/30投球回以内×支配下5年以内なら資格が残る（2年目ブレイクの新人王が出ない）。

### [B] タイトルが同数タイで単独受賞＋最多安打・最高出塁率が欠落 `src/game/awards.mjs:98-146`
タイは playerId 辞書順で1人に確定（NPBは同数なら両者受賞）。タイトル一覧に最多安打・最高出塁率が無い。

### [B] MVPが純粋なリーグWAR首位（チーム成績と無関係） `src/game/awards.mjs:150`
現実のMVPは記者投票で優勝チーム偏重。最下位チームからMVPが平然と出る。

### [B] 戦力外選手が全員NPB内に再分配され、球界からの退出が無い `src/game/transactions.mjs:330-358` / `src/game/roster.mjs:922`
拾い上げは提出=獲得の全単射（構成恒常）で、拾われず引退する選手が存在しない。加えて retire.minAge=32 のため **32歳未満は絶対にリーグから消えない**（現実は20代の戦力外→引退が毎年大量に出る）。意図的な構成恒常の簡略化だが、キャリア画面・ニュースで見える。

### [B] 外国人選手・外国人枠という制度が存在しない（コードベース全体に不在）
NPBの編成の根幹要素（一軍4人枠・新外国人獲得・当たり外れ）が世界にない。完全架空リーグの設計判断ではあるが、「セパ近似」の観点では大きな欠落。

## 9. 加齢・故障

### [A] 故障がオフシーズンにしか発生しない `src/game/injury.mjs:28-36` / `src/game/index.mjs:77`
applyInjuries はオフ遷移でのみ呼ばれ、全故障者が「開幕からのIL」になる。シーズン中の離脱・故障ニュースが存在せず、gamesLost の消化パターンが現実と全く違う。

### [B] 故障ハザードが使用量と無関係 `src/game/injury.mjs:43-63`
年齢・役割・球速・捕手・故障歴のみ。投球回200のエースと20の敗戦処理が同リスク。

### [B] 投手の軽症故障は投球能力に後遺が残らない `src/game/injury.mjs:92-103`
minor の後遺は speed/reaction/power/打撃EV のみ＝投手の軽い故障が「打撃と足だけ」落とす奇妙な挙動。

### [B] 新人が「完成品」で入団する `src/generate.mjs:295-307`
generateRookie は現役選手と同一分布から引いて年齢だけ18-22に書き換える。18歳が入団時点でNPB平均級でありうる（現実の高卒は入団時点では大きく下で、二軍で成長する）。※加齢モデル自体には成長相（growEnd まで+grow、若手は gm 分散）が実装済みなので、「上りが無い」わけではない＝入団時レベルの問題。

### [B] 俊足選手ほど全能力が早く衰える（declineRate が speed 正相関の一括係数） `src/generate.mjs:204`
dr は選球眼や contact の衰えにも一括で掛かる。捕手（鈍足）が最も dr が低く長持ちしやすい（故障ハザード側の catcher 加算で一部相殺されるが、現実の「捕手は消耗が激しい」とは方向が合わない）。

## 指標定義（メトリクス）の乖離 — 別クラスタ

1. **[B] FIP/xFIP が IBB を除外** `src/sim/metrics.mjs:234` — FG式は BB+HBP（IBB込み）。uBB を使うのは wOBA。fipConstant 側も同式のためリーグ恒等は保たれるが個人分布が歪む。正典 sabermetrics_glossary.md §3.4 と矛盾。
2. **[B] wRC+ のパーク補正が除算式** `src/sim/metrics.mjs:80` — FGは加法補正（リーグ平均分の球場超過を加減）＋非投手 wRC/PA 分母。良い打者ほど過大に割り引かれる。
3. **[B] リーグ定数がセパ合算** `src/sim/leagueConstants.mjs:40` — ERA-/FIP-/wRC+ の基準が両リーグ合算のため、DH有リーグの投手が構造的に不利に見える（FG/1.02はリーグ別）。
4. **[B] WARの打撃・投球成分がパーク非補正** `src/sim/war.mjs:56,79` — D2のPFは表示用(wrcPlusPF等)にのみ接続。打高本拠地の野手WARが系統的に上振れ。
5. **[B] 投手WARが静的RPW** `src/sim/war.mjs:79` — FGは投手固有 dRPW。エース級ほど過小。またヘッダの「0.12/0.03」と config 実値（0.166/0.014）が不一致（ドキュメント腐り）。
6. **[B] UZR成分が主ポジション一括判定** `src/sim/fielding.mjs:168` — 実UZRはポジション別算出の合算。ユーティリティ選手の守備runが歪む。
7. **[B] LIがΔWEのRMS定義** `src/sim/context.mjs:240` — 原典は確率加重平均。分布の裾が太る。
8. **[B] 線形ウェイトが固定定数** `src/sim/leagueConstants.mjs:15` — FGは年次再導出。時代トレンドで得点環境が動く多年プレイで相対価値が固定のまま。

## 修正の推奨順序（私見）

1. **走塁の 'out' 分岐の作り直し**（ゴロ進塁・犠飛の深さ依存・失策進塁・2死の走塁死）— §1 の4件は同じ関数群（advanceRunners/resolveAdv）に閉じており、一体で設計し直すのが効率的。得点手段の分布が現実に近づく最大の一手。ただし得点環境の較正53指標に直撃するため、tuning 再較正とセット。
2. **塁打決定の守備隊形依存化**（decideBases に落下点×野手位置を入れる）— 発端の穴。1と同時にやると進塁確率の意味論が揃う。
3. **継承走者の失点帰属**（runLog に走者の出所を持たせる）— ERA分布の構造欠陥。
4. **采配の欠落4点**（クローザー同点投入・先頭打者代打・スクイズ・失点あり完投）— manager.mjs のゲート追加で比較的独立に直せる。
5. **HR帯の解消**（フェンス越え落下点は必ずHR＝hrScale をフェンス側でなく飛距離側に適用 or 判定順序変更）＋LA<15°の柵越え。
6. 記録規則（PB非自責・サヨナラ決勝点まで・セーブ規定・WP犠飛）— 得点環境に影響しない記録層なので低リスク。
7. 日程の3連戦カード化・交流戦期間化 — UI体験の向上大、シム本体への影響小。
8. 指標定義8件 — 較正への影響を確認しつつ個別に。
9. 制度系（FA補償・新人王・タイトルタイ・ドラフト折返し・戦力外退出・故障のシーズン中発生・3連投許可）— ゲーム層の意思決定で優先度を判断。
