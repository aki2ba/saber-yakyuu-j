# GM分析仕様 — データを意思決定に接続する（フォーム判定・GMボード・トレードAIのセイバー視点）

> 根拠: ユーザー指示 2026-07-23「セイバーの常識的な知識で語る」「トレードとか一軍-二軍入れ替えに
> 活かしたい」「他球団の有望な若手を把握してトレードしかける」「自球団と他球団の弱点と選手の飽和を
> すぐ見れるように」「トレード受諾（AI）にもセイバー的視点を」。
> `thyroxin/research/data_storytelling_research_20260723.md`（R2/R3の発展形）を土台に、
> 表示だけでなく**意思決定への接続**まで踏み込む。実装担当（Sonnet）はこの文書だけで完遂できること。

## 0. 全体ルール（厳守）

1. **観測のみ**: すべての判定・表示は観測成績（rt.stats/careerStats/farmStats）とスカウト等級
   （既存の見立て座標）から。真値(trueAbility)・能力値レーティングへの依存禁止（現行の能力値表示UI
   は現状維持・触らない）。
2. **セイバー定説準拠**: 文章・判定ロジックの根拠は定説のみ（xwOBA系乖離=回帰予兆 / BABIP極端値=
   平均回帰 / K-BB%=投手の先行指標 / O-Swing%=早期安定・選球眼 / 小サンプルは語らない）。
   各判定のコメントに根拠定説を1行明記。
3. 決定論: hashSeed 独立座標のみ。表示層は純関数・保存フィールド追加なし（毎回導出）。
4. 較正不変: Wave B/C は表示層のみ＝byte不変。Wave D はオフシーズンAIの挙動変更（1年目シーズン
   成績には非干渉＝calibrate 53指標は構造上不変）だが、多年テスト（E3等）への影響は要確認。
5. トップレベル宣言名は全モジュール横断で一意（バンドル同一スコープ制約）。

## Wave B: フォーム判定（好調/不調）— formIndex

**新モジュール `src/game/form.mjs`（純関数）**

- `playerFormOf(state, playerId)` → `{ tier: 'hot'|'normal'|'cold'|null, reasons: [{text, kind}] }`
  - 野手: 直近窓（自チームは playerGameLog の box 直近10試合ぶん・他球団は月次分割が無いため
    シーズン累計との比較はできない→**他球団はシーズン累計の指標のみで語る**（乖離型）。
    自チーム: 窓wOBA vs シーズンwOBA（±.040でhot/cold候補）＋K%窓トレンド。
    **表層×セイバー併用**: 「直近10試合 .333 と当たっているが窓BABIP .450 は出来すぎ」型の
    ガードを reasons に含める（見かけの好調に印をつける＝定説2の応用）。
  - 投手: 直近3登板の K-BB%・失点 vs シーズンSIERA系（metrics.mjs にある範囲で）。
  - 最低サンプルゲート（窓20打席/窓6イニング未満は tier=null＝語らない）。
- 表示:
  - チームタブ（一軍/二軍一覧）に ▲(hot)/▼(cold) バッジ＋ホバー/クリックで reasons。
  - 出場登録入替（roster_moves の UI 表示箇所）に「入替候補の根拠」として reasons を併記
    （usage AI の判断自体は変えない＝表示で人間の判断を支援するだけ）。

## Wave C: GMボード — 弱点・飽和・有望若手・トレード相手サジェスト

**新モジュール `src/game/gmBoard.mjs`（純関数）＋ チームタブに「GM」サブタブ（新節）**

1. `positionStrengthMap(state)` … 12球団×守備位置の「観測戦力」ヒートマップ素材。
   各球団・各位置のレギュラー（出場イニング/先発数最多の選手）の観測 wOBA（守備位置補正なしの
   素朴版でよい・投手はローテのK-BB%平均と救援のFIP平均）をリーグ内百分位化。
   → **弱点**=下位20%（赤）/ **飽和**=同一位置に規定30%以上の観測上位選手が複数（青）。
2. `prospectWatch(state)` … 他球団の有望若手リスト: 年齢≤25 × 観測指標が年齢比で優秀
   （wOBA/K-BB%のリーグ百分位×若さ）× **飽和ポジションで出場機会が細い**（=狙い目タグ。
   「塞がれている有望株」はトレードで動く、という現実のGM定説）。farmStats（二軍観測）も対象
   （R2「二軍の逸材」の発展）。
3. `tradeTargetSuggestions(state)` … 自球団の飽和位置×相手の弱点位置のマッチング上位
   （「あなたの三塁は飽和・◯◯球団の三塁は弱点——トレードの窓がある」）。既存 proposeTrade UI への
   導線ボタン付き。
4. UI: チームタブ内「GM」節（新タブ追加はボタン文言変更に当たらない・smoke既存アサーション
   非破壊を確認）。ヒートは既存 heat トークン（--heat-hi/lo）流用。

## Wave D: トレードAI受諾のセイバー視点（エンジン層・オフシーズンAIの挙動変更）

**`src/game/transactions.mjs` / `src/game/market.mjs`**

1. `saberSavvy` を teamEvalProfile へ追加。**必ず独立シード**
   `makeRng(hashSeed(masterSeed,'evalprofile',teamId,'saber'))` で引く（既存 r の連番 draw に
   追加すると全球団のプロファイルが世界ごと引き直しになる＝禁止。independent-coordinate の前例
   多数）。分布: 0..1（例 clamp(normal(0.5,0.25),0,1)）。**市場非効率の鉄則5と整合**＝
   セイバー度の高い球団は回帰込みの真に近い評価・低い球団は表層スタッツ寄りの評価をする。
2. `regressedValueOf(p, obs, cfg)`（新・純関数）: observedValueOf の回帰調整版。
   - 野手: wOBA を「BABIP乖離の平均回帰」で補正（窓ではなく当季累計 BABIP がリーグ平均から
     大きく乖離していれば定説どおり半分程度を戻す）＋ PA が少ないほどリーグ平均へ縮約
     （regression to the mean・簡易ベイズ）。
   - 投手: FIP をそのまま（既にDIPS定説準拠）＋ HR/FB 的な乱高下項が無いので LOB%的補正は
     行わない（データに無いものはでっち上げない）。K-BB% を将来予測の重みに使う。
   - 年齢カーブ割引: 30歳超は残存価値を逓減（老化の定説・ageBias とは独立の客観項）。
3. トレード評価の合成: AI球団の主観価値 = `(1−saberSavvy) × 従来評価 + saberSavvy × regressed評価`
   ＋ **ポジション需要項**: 受け手の弱点位置を埋める選手は主観価値+（positionStrengthMap の
   百分位から決定論導出）。飽和位置の選手は−。
4. 受諾判定（人間からの proposeTrade も AI 間トレードも同じ関数を通す）: 従来の合意条件に
   上記主観価値を使う。**結果**: セイバー度の低い球団には「表層が地味で回帰的に上振れる選手」を
   安く出させられる＝プレイヤーがGMボードの分析で市場非効率を突ける（鉄則5の完成形）。
5. ゲート: 1年目 calibrate 53指標は構造上不変（トレードはオフ発生）。多年テスト（game_e3 の
   トレード成立性・multiyear バンド）は要実行確認。挙動が変わって然るべきテスト（成立件数等）は
   意図を明記して調整可・ただし「WAR-6根絶」「リーグ均衡」系の恒常ゲートを壊すことは不可。

## 実装順とゲート

Wave B → C → D の順（B/C は表示のみで低リスク・D はE3/multiyear 再確認が必要）。

必ず報告に含める）。
