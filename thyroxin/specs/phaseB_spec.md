# フェーズB 実装仕様: 一球ごとシミュレーション＋セイバー指標大拡張（req_2 原則1）

> 前提: フェーズA完了（12球団2リーグ・ベンチ/起用AI・采配・役割別repl）。
> 分割: **B1=一球シム化**（エンジン改造）→ **B2=文脈指標**（RE24/WPA/LI）→ **B3=指標スイート＋UI**。
> 各サブフェーズ完了時に npm test / verify / smoke / calibrate 全PASS＋コミット。
> 原則: 指標は後付けせず、一球・一プレーの副産物として生カウントから湧かせる。

## B1: 一球ごとシミュレーション（カウント状態機械）

### B1-1. ピッチループ
`plateAppearance.mjs` の一発抽選を **(balls, strikes) カウント状態機械**へ置換:

1. **球種選択**（pitchGrid拡張）: カウント依存の重み（追い込まれ前=速球寄り、決め球=whiff最大球種、3ボール=制球しやすい球）×投手の球種構成。
2. **投球ロケーション**: ゾーン内率 = f(投手control, カウント)。ビハインドカウント(3-0,3-1,2-0)→ゾーン内率↑、0-2,1-2→ボール球で釣る。実装はゾーン内/ボーダー/明確ボールの3帯で十分（座標格子は段階2）。
3. **打者スイング判断**: Swing% = f(ゾーン帯, eye, カウント)。O-Swing(ボール球スイング)はeyeで減、2ストライクでは保護スイング↑、3-0は自重。
4. **スイング時**: 空振り率 = f(球種whiff, 打者contact, ゾーン帯, 対球種適性)。当たれば ファウル vs インプレー分岐（2ストライクのファウルはカウント維持）。インプレー→既存のEV/LA打球パイプラインへ（変更なし）。
5. **見逃し時**: ゾーン内=ストライク、ボーダー帯=**捕手フレーミングで判定が動く**（framing能力→ボーダー球のストライク率±。現行の per-inning 近似 framingRuns を廃止し、一球単位の創発に置換）、外=ボール。
6. **HBP**: 内角外れの低確率イベント（現行率を維持）。
7. **暴投/捕逸**: ワンバウンド球確率×捕手blocking能力（新能力軸 `fielding.blocking`）→ 走者進塁。WP(投手)/PB(捕手)を計上。
8. K=3ストライク目、BB=4ボール目として**創発**させる（regulation層のlog5は廃止し、一球パラメータへ再較正）。TTOペナルティは一球単位で適用。

### B1-2. 生カウント追加（statline.mjs）
- batting/pitching 双方に: `pitches, swings, whiffs, fouls, calledStrikes, zonePitches, zSwings, zWhiffs, oZonePitches, oSwings, oWhiffs, ballsInDirt` 等（対称に）。
- 捕手 fielding に: `frameCalls`（ボーダー球のストライク獲得−リーグ平均）, `wp, pb, blockOpp`。
- カウント別成績（`byCount` は 12セル×フルは重いので、**ahead/even/behind の3分類＋0-2/3-0 の代表4セル**に圧縮して保持）。

### B1-4. 性能
- 一球イベントは**使い捨てオブジェクトを作らない**（カウンタ直接加算・再利用構造体）。858試合×~290球/試合×2で ~50万球/シーズン。較正5シードが現実的時間（<60s）で回ること。ボトルネックならプロファイルして最適化。

## B2: 文脈指標（RE24 / WPA / LI / Clutch）

1. **RE24**: 24状態(塁×アウト)の得点期待値行列を**シム自身から導出**（較正ランで大標本→leagueConstantsへ焼き込み。2パス目で参照）。一打席・一プレーごとに ΔRE を打者/投手に付与（盗塁・暴投等の走塁イベントは走者に）。恒等式: リーグ総和≈0（自チェック）。
2. **勝率表(WE)**: (イニング, 表裏, 点差クリップ±8, 塁アウト状態) → 勝率。導出は較正ランの実測頻度＋平滑化。leagueConstantsへ。
3. **WPA**: 一プレーごと ΔWE を打者(+)/投手(−)へ。ゼロサム検査（1試合の総和=±0.5→勝敗と一致）。
4. **LI**: 状態のレバレッジ指数（WE分散ベース、リーグ平均=1.0へ正規化）。aLI(打席加重平均)・pLI(投手)・**gmLI**(救援の登板時LI)。
5. **派生**: WPA/LI(文脈中立勝利)、**Clutch = WPA/pLI − WPA/LI**、SD/MD(シャットダウン≥+0.06 / メルトダウン≤−0.06)。
6. **救援WARのレバレッジ加重**: 救援の代替水準対比runに `(1+gmLI)/2` を乗じる（FG方式）。req_1 §8.3「WARの死角」の完成。
7. 較正チェック: リーグΣRE24≈0、ΣWPA(勝チーム)−…ゼロサム、平均LI≈1.0、SD王 30-45 / MD数の分布。

## B3: 指標スイート＋UI

### 投手
- **xFIP**（lgHR/FB を使用・要 投手別被打球タイプ計上）、**SIERA**（FG公開式）、**kwERA** = 5.40 − 12×(K%−BB%)
- **ERA− / FIP− / xFIP−**（リーグ=100基準。パーク補正はフェーズD）
- K-BB%、K/9・BB/9・HR/9、**LOB%** = (H+BB+HBP−R)/(H+BB+HBP−1.4HR)、被BABIP、被GB/FB/LD%、HR/FB
- **QS**、**IR/IRS**（継承走者と生還数。交代時に走者責任を投手IDで持つ＝A-3継承走者誤帰属もここで修正: 失点は走者を出した投手の自責へ）
- プレートディシプリン被 (被O-Swing等=「釣れる投手」)

### 打者
- OPS+、wRC、TB、XBH、SecA、BB/K、**Spd**(簡易4成分)
- **xBA/xSLG/xwOBA**: 打球解決モデルが持つ期待確率（expOut・塁打分布）を**rng抽選前に**そのまま累積（モデル=シムなので恒等: リーグ xwOBA≈wOBA が自動成立→較正チェックに使う）
- **Barrel%**（EV×LA格子の最適帯）、**HardHit%**(EV≥152km/h)、平均EV/最大EV、Sweet-Spot%(LA 8-32°)、GB/FB/LD/PU%、Pull/Cent/Oppo%
- スプリット: **対左/対右・得点圏(RISP)・ホーム/ビジター**（statlineにコンパクトなスプリット器を追加。カウント別はB1-2の圧縮版）

### 守備・走塁
- UZR成分分解の完成: **RngR(OAA由来)+ErrR+ARM+DPR**＋フレーミング(捕手)
  - **ARM**(外野): 走者追加進塁の抑止/補殺。resolveAdv に外野手のarm を接続し、送球死(補殺 a++)・自重(進塁抑止)を生成 → リーグ平均対比run
  - **DPR**(内野二遊): 併殺転換率の対平均run
  - 捕手: フレーミングrun(B1)・**盗塁阻止run(rSB)**・**ブロッキングrun**(WP/PB抑止)
- 走塁: **XBT%**(追加進塁率)、走塁死、**Spd**、BsR=wSB+UBR+wGDP は成分表示

### UI
- 選手モーダルをタブ化: 基本 / 打球(スプレー+EV/LA分布+Barrel%) / ディシプリン(O-Swing表) / スプリット / 文脈(WPA・RE24・Clutch) / 守備成分
- リーダーボードに新指標列（ソート可・ツールチップに定義説明=初心者への配慮）
- チーム集計タブ（チーム打撃/投手/守備/走塁のリーグ内順位）

### 較正チェック追加
- リーグxwOBA≈wOBA(±.003)、ΣRE24≈0、WPAゼロサム、LI≈1.0、SD/MD分布、ARM上位+5〜12、Spd分布、QS率 45-60%、LOB% 70-75%

## 実装順・依存
B1(一球化)が全ての土台。B1完了→較正回復を確認してから B2(RE24/WPA はイベントストリームに依存)→B3(集計と表示)。
B3の xBA系は B1と独立（現行打球モデルでも可）なので、B1が難航したら B3先行も可。

## 禁則
- 決定論維持（一球化で乱数消費数が変わるのは可。同一シード同一結果は必須）
- 生の一球ログの永続化はしない（カウンタ集計のみ。§17 メモリ制約）
- 較正の器(config)集約・三層構造・manager/usage分離はフェーズAの規約を踏襲
