# フェーズC 実装仕様: ゲーム層 — やきゅつく的プレイ感（req_2 原則3）

> 前提: フェーズA完了（起用/采配AIがポリシーとして分離済み）。フェーズBとは独立に着手可能（B完了後なら観戦モードが一球単位になる）。
> 分割: **C1=ゲームシェル**（1シーズンを"プレイ"できる）→ **C2=キャリア**（複数年・育成 = req_1フェーズ3統合）→ **C3=編成市場**（ドラフト/FA/トレード）→ **C4=演出**（ニュース/表彰/記録）。
> スコープ外(v1): 経営・資金・スタジアム運営（やきゅつくの経営要素は楽しさの核=育成・編成・采配を固めた後に検討。progress.mdバックログに残す）。

## 設計原則
- **エンジンとUIの分離**: 新設 `src/game/` にヘッドレスなゲームループAPIを置き、UIはその表示に徹する。
  - `newGame(masterSeed, playerTeamId, options)` → GameState
  - `advanceDay(state)` / `advanceTo(state, until)`（次の自チーム試合まで/月末まで/シーズン終了まで）
  - `save(state)` / `load(blob)`（バージョン付きスキーマ・RNG状態込み・決定論復元）
  - すべて node --test でヘッドレステスト可能にする（UI無しで1キャリア回せること）
- **人間の采配 = manager/usageポリシーの差し替え**（フェーズAのフックを使う）。「おまかせ」=既存AI。
- 自己完結HTML維持（build.mjsバンドル・外部依存なし・SVG/CSSのみ=req_1 §16 Lv2）。

## C1: ゲームシェル（1シーズンをプレイできる）

1. **画面フロー**: タイトル → ニューゲーム（12球団から自チーム選択・シード指定可） → **シーズンハブ** → 試合 → …… → ポストシーズン → シーズンリザルト。
2. **シーズンハブ**（ホーム画面）: 日付/順位表/次戦カード/直近結果/チーム状態（疲労・調子）/リーダーボードへのリンク。進行ボタン: 「次の試合へ」「1週間」「月末まで」「シーズン終了まで」。
3. **日次進行**: フェーズAのdayカレンダーを消費。自チーム試合日は選択: **観戦**（介入あり）/ **ダイジェスト**（イニング要約）/ **スキップ**（結果のみ）。他球団は自動消化。
4. **采配介入**:
   - シーズン設定: スタメン/打順/守備位置/ローテ順/ブルペン役割/方針（バント積極性・盗塁積極性・継投早さ＝監督プロファイルを自チームだけ人間が上書き）
   - 観戦中: 打席前ポーズ→ 代打/バント/盗塁指示/敬遠/申告故意四球、守備側→ 投手交代/敬遠。UIは打席単位（フェーズB後に一球単位へ拡張）。
   - 「おまかせ」トグルで全部AIに委任可（ダイジェスト勢の遊び方）。
5. **試合観戦UI**: スコアボード＋ダイヤモンド盤面（SVG）＋テキスト実況（打席結果・打球のEV/LA/落下点を言語化=セイバー感の演出）＋ベンチ/ブルペン残量表示。
6. **セーブ/ロード**: IndexedDB（localStorage不可 §17）。スキーマ `{schemaVersion, engineVersion, masterSeed, day, year, playerTeamId, players[], careerStats[], seasonState, rngCursors, settings}`。オートセーブ（日次）＋手動スロット3。ロード後の決定論継続をテストで保証。
7. **Web Worker**: 「シーズン終了まで」等の長時間進行をWorkerで（UIスレッド不凍結・プログレスバー §17）。階層シードにより分割実行でも結果不変。

### C1較正・検証
- ヘッドレスで new→advance→save→load→advance の一致性テスト（決定論）
- スモーク: 観戦1試合＋ハブ画面＋セーブ/ロードのUI経路

## C2: キャリア層（複数年・育成 = req_1フェーズ3の統合）

req_1 §10/§12 の仕様に従う（詳細はreq_1参照。ここでは統合順序と接続点のみ規定）:

1. **オフシーズンフェーズ**（シーズン終了→翌年開幕の状態遷移）: 表彰(C4)→ 戦力外/引退 → ドラフト(C3) → 契約更改(簡易: 年俸=直近WAR連動のフレーバー表示) → キャンプ(育成方針) → 開幕。
2. **能力別加齢カーブ**（3-1/3-2）: peakAge/declineRate個体差・技巧系は残る・選球眼は伸びる。オフシーズンに真値へ適用。
3. **成長ドリフト＋ブレイクイベント**（3-3/3-4）: 若手高分散・bust多め。上方=球種習得/覚醒/EVジャンプ、下方=制球崩壊/燃え尽き。**プレイヤーの育成方針**（キャンプでチーム重点: 打撃/投球/守備/走塁、個人指定枠2-3人）は成長ドリフトの平均を微シフト（ノイズ>方針 の原則は崩さない=万能育成にしない）。
4. **故障ハザード**（3-5）: 年齢・ポジション・投球量・故障歴。シーズン中の離脱（出場不可日数）→ 起用AI/ベンチが自然に穴を埋める（フェーズAの資産）。故障情報はハブに表示。
5. **引退・世代交代**: 能力/年齢/出場機会から引退判定。ドラフトで新人補充（リーグ人口恒常性）。
6. **通算成績**: careerStats（選手×年の行）。通算リーダーボード・個人ページに年度別成績表。

## C3: 編成市場

1. **球団AI評価関数の球団差**（req_1 §15/§13: わざと不完全に。守備/位置価値を過小評価する球団、出塁軽視の球団等）→ 宝拾い・割安の市場非効率を仕込む。
2. **ドラフト**: 世代生成（高卒18/大卒22/社会人25相当の年齢分布）、スカウト観測ノイズ付きの指名リスト、ウェーバー逆順×くじ（1位競合抽選=NPB風）。プレイヤーは指名操作（おまかせ可）。
3. **FA**: 国内FA相当（年数条件は簡略: 一定年齢+実績で権利）。宣言選手に球団AIが評価関数で入札、プレイヤーも参加。
4. **トレード**: AI同士は評価差から成立判定。プレイヤーへのAI提案＋プレイヤー起案（AIは自評価関数で受諾判定）。
5. **戦力外→拾い上げ**（§12.2の構造発現）: 少ない/歪んだ観測で切られた選手を他球団が拾う。育成/支配下二層はここで導入（§12.1）。

## C4: 演出・記録（やきゅつくのエモさ）

1. **ニュースフィード**: 週次ダイジェスト（首位攻防・連勝/連敗・怪我人・月間MVP・猛打賞/完封等の見出し生成。テンプレ文＋実データ差し込み）。ノーヒットノーラン/サイクル安打の検出。
2. **表彰**（シーズンリザルト画面): MVP/新人王/ベストナイン/守備の栄誉賞(UZR+OAAベース=架空名)/タイトル（首位打者・本塁打王・打点王・盗塁王・最優秀防御率・最多勝・最多奪三振・最優秀中継ぎ・最多セーブ）。受賞履歴は選手ページへ。
3. **記録**: 球団史（年度別順位・日本一）、リーグ記録（シーズン/通算のトップ10）、達成マイルストーン通知（2000本安打/200勝/250S 等の架空リーグ記録文脈）。
4. **選手の顔**: 画像は使わない（§16 Lv4回避）。能力レーダー/成長曲線SVG＋フォーム・二つ名テキスト（「精密機械」「韋駄天」等を能力パターンから自動付与）でキャラ立ち。

## 実装順
C1 → C2 → C3 → C4 の順（各完了ごとにテスト+スモーク+コミット）。C2以降は req_1 フェーズ3のチェックボックスも消し込む。
フェーズB完了後: 観戦モードを一球単位化（実況にカウント/球種/コース）、WPAリアルタイム表示（勝利確率グラフ=試合のドラマ可視化）。

## 禁則
- エンジン決定論を破らない（UI操作もイベントとしてシード化された進行に乗せる。人間介入後の再現性は「介入ログ」をセーブに含めることで担保）
- 生イベント肥大化禁止（§17: 集計値のみ永続、生打球は当該シーズンのみ）
- trueAbilityをUIに直接出さない（プレイヤーが見るのは観測成績とスカウト評価=三層構造。育成画面も「コーチの見立て」表現にする）
