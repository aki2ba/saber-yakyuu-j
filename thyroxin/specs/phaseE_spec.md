# フェーズE 実装仕様: UI/UX刷新（ユーザーフィードバック 2026-07-05）

> ユーザー指摘（原文要旨）: 「自チームの選手一覧がない・二軍が見えない・トレードができない・全体的にUI/UXが悪すぎる。
> 特に試合は見れたものではない。選手のデータも見れない。**スポナビの野球速報みたいなのがいい**」
> 全国対戦の後回しは合意済み。優先順: E1選手一覧 → E2観戦刷新 → E3編成操作 → E4動線磨き。

## 前提（実装済みの資産・エンジンは触らない方針）
- `src/ui.mjs`(1,634行) にゲームシェル(renderHub/renderWatch等)と分析UI。選手詳細モーダル(renderModalBasic〜Career・タブ式)は実装済み。
- **観戦フック**: `simulateGame` に `opts.onEvent`（乱数非消費・決定論を壊さない構造化イベント）が既にある。観戦は `game.watch={rec,events,idx,progressive}` で1プレーずつ送る方式。
- **二軍**: `league.farm`＋`rosterStatus`(支配下/育成) はエンジン実装済み。UIから見えないだけ。
- **市場API**: `bidFA(state,playerId)`/`proposeTrade(state,aPlayer,bPlayer)` 実装済み（介入ログでセーブ再現）。UIから呼ばれていないだけ。
- 一球データ: フェーズB1のカウント状態機械が投球ごとの内部状態を持つ（イベントとして emit するには game.mjs の onEvent 発火点追加が要る＝**乱数非消費・挙動不変を厳守**）。

## E1: 自チーム運営ハブ（選手一覧）— 育成ゲームの背骨
- ハブに「チーム」タブ新設: **一軍(支配下)/二軍(育成)** のサブタブ。
- 選手一覧テーブル: 野手(位置/年齢/打席/AVG/OBP/SLG/OPS/HR/打点/盗塁/wRC+/WAR/スカウト等級/状態[故障/離脱]) と投手(役割/年齢/登板/IP/ERA/FIP/WHIP/K-BB%/SV/HLD/WAR/等級/状態) を分けて表示。列ソート可（既存statTableの流儀）。
- **全行クリック→選手詳細モーダル**（既存のタブ式モーダルへ）。育成選手も開ける。
- 選手詳細に「所属(一軍/育成)・年齢・利き手・二つ名・受賞歴」ヘッダを整備。
- **導線の全画面化**: 順位表/表彰/ニュース/記録/観戦画面の選手名をすべてクリック可能に（共通ヘルパー playerLink() を作り既存表を置換）。

## E2: 試合観戦のスポナビ風刷新 — 最重要の体験改善
レイアウト（スポナビ野球速報を参考に、完全自作のCSS/SVG）:
1. **上部: ラインスコア**（イニング別得点 R/H/E 付き、9回+延長列）— rec からイニング別得点を集計。
2. **中央左: フィールド盤面**（既存ダイヤモンドSVGを拡張: 塁上走者の選手名表示・アウトカウント・B/S/Oランプ）。
3. **中央右: 対戦カード** — 現在の打者(今日の打席結果列＋シーズンAVG/HR/OPS)と投手(球数/今日の投球内容＋シーズンERA/K)。名前クリック→詳細モーダル。
4. **下部: 一球速報テキスト** — 「1球目 ストレート ボール (1-0)」「2球目 フォーク 空振り (1-1)」…打席結果で「レフトへのタイムリーツーベース！」等。
   - 実装: game.mjs の一球ループに onEvent({type:'pitch', ...カウント/球種/判定}) を追加発火（**rng非消費・結果不変**。verify identity が byte 一致することを必ず確認）。
   - 観戦の進行単位を「1球ずつ / 1打席ずつ / 1イニングずつ」で切替可能に（連打しなくても見られる自動再生トグルも）。
5. **サイド/折りたたみ: 両軍スタメン表**（打順・位置・当日成績 2-4(第4打席) 風）＋ベンチ・ブルペン残量（既存表示を統合）。
6. 交代・盗塁・エラー等のイベントも実況行に整形（既存イベントの言語化を拡張）。

## E3: 編成操作UI — エンジンAPIの解放
- オフシーズン画面（シーズンリザルト→年送りの間）に「ストーブリーグ」ステップを新設:
  - **FA市場**: 宣言選手一覧(成績/年齢/等級)→ bidFA で入札。結果はオフ要約に表示。
  - **トレード**: 自チーム選手×相手選手を選んで proposeTrade。AIの受諾/拒否と理由（評価差）を表示。AIからの提案も受ける。
  - **育成⇔支配下**: 昇格候補(育成の観測成績)一覧と昇格希望の指定（エンジンの昇格判定に希望を反映できる範囲で。困難ならエンジンの自動昇格結果の可視化＋次年度の枠訓示でも可）。
- 介入はすべて既存の marketInterventions ログに乗せ、セーブ→ロード→リプレイで再現（決定論）。
- オフ要約画面（引退/ドラフト/FA/トレード/拾い上げ/表彰）を1画面のダイジェストに整理。

## E4: ナビゲーション/日程/ニュース動線
- ハブのタブ整理: ホーム / チーム(E1) / 日程・結果 / 順位 / 成績(打・投・守・WAR) / ニュース / 記録。
- **日程・結果タブ新設**: 月別カレンダー or リスト（自チームの全日程・スコア・勝敗マーク・クリックで簡易ボックススコア=両軍打者/投手の当日ライン）。
- ニュースの見出しから該当選手/試合へリンク。
- 操作の一貫性: 戻るボタン・現在地表示・ボタンのdisabled状態・進行ボタンの配置統一。
- スマホ想定の縦積みレイアウト対応（狭幅で表が横スクロール）。

## 検証・制約
- エンジン挙動は不変: `npm run verify` の identity byte一致・`npm run calibrate` 53指標不変が門番（onEventの追加発火はrng非消費）。
- `tools/smoke-ui.mjs` に新画面の描画・導線（チームタブ→選手モーダル / 観戦の一球速報 / ストーブリーグ操作 / 日程→ボックススコア）のアサーションを追加。
- 決定論: UI操作（トレード/FA/観戦速度）はセーブの介入ログに乗るものだけが状態を変える。
- 自己完結HTML・SVG/CSSのみ・外部依存禁止。日本語UI。
