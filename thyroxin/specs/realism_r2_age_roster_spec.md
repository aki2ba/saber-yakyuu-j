## 1. 実測で確定した欠陥（すべて再現可能・scratchpad の probe_*.mjs）

| # | 欠陥 | 実測値 | 現実（NPB） |
|---|------|--------|-------------|
| 1 | **年齢と能力が完全に無相関** | r = 0.012。18歳の平均 overall 51.1 = 30歳の 51.0 | 山なり（26-29ピーク）＋生存バイアス |
| 2 | **リーグ上位が10代で埋まる** | リーグ overall 2-3位が18歳。18歳でパワー80（生成上限） | 高卒新人がリーグ2位は起こらない |
| 3 | **支配下の年齢分布が18歳に極端集中** | 支配下840人中 18歳163人（19%）＝13.6人/球団 | 18歳は高卒ドラフト分の2-3人/球団 |
| 4 | **一軍が高卒新人だらけ** | 一軍登録29人の平均年齢 23.9歳／20歳以下が38% | 一軍出場選手の平均は28歳前後 |
| 5 | **規定到達者の36%が20歳以下**（18歳だけで19%） | 3seed 327人中118人 | 高卒1年目の規定到達は数十年に数人 |
| 6 | **若手が育たない**（③やきゅつく的楽しさの喪失） | aging の grow が power/ev=0.2/年。18→27歳の9年で **+1.8pt** | 高卒新人が主力に育つのが物語の核 |
| 7 | **1年目は一軍/二軍の入替が一切起きない** | `enableMoves: state.yearIndex > 0`（index.mjs:150） | 故障者の抹消・二軍からの昇格は日常 |
| 8 | シーズン中の入替が少ない | 11-12件/球団/年（うち成績入替8件） | （要参照値・調査中） |

### 欠陥6と1-5は同根（構造的な循環）
`generate` が「年齢と無関係に完成品を生成」しているため、`aging` の成長を効かせると
母集団が上振れして得点環境が単調インフレする（§11.3 Bug1）。それを止めるために
**加齢の grow をほぼゼロまで潰してある**（config.mjs の★Bug1コメント）。
つまり「生成の誤りに合わせて加齢を歪めた」状態＝ 2つを同時に直さないと解けない。

## 2. 設計（生成と加齢を同一カーブに載せる）

**核心**: `generatePitcher/generateFielder` が生成するのは **ポテンシャル（成長終端＝peak時の能力）** とし、
現在能力は「age までカーブを進めた値」として導出する。これで生成と加齢が同じ関数になり、
「生成された28歳」と「18歳から育った28歳」が同分布になる（内部整合）。

### A. 成熟度カーブ `applyMaturity(p, cfg)`（新規・generate.mjs）

`cfg.tuning.aging.profiles` を**そのまま逆算に使う**（加齢と同一の grow/decline/peakShift/declineOffset）。
能力キーごとに個別に適用する＝**能力タイプ別の成熟差が自然に出る**（走力は早熟・技術は晩成）。

```
maturityDelta(key, age, peak, dr, aging):
  prof    = aging.profiles[key] ?? aging.profiles.default
  growEnd = peak + prof.peakShift
  onset   = peak + prof.declineOffset
  d = 0
  if age < growEnd:  d -= prof.grow * (growEnd - age)          // まだ成長していない分
  if age > onset:    d -= Σ_{k=1..(age-onset)} prof.decline * dr * (1 + accel*(k-1))  // 既に衰えた分
  return d
```
- 衰え側は `aging.declineAccel` の累積を**加齢と同じ式で積分**する（1年ずつ足す。ループでよい・age≤37なので最大~10反復）
- 球速は `aging.velo` の grow/decline で同様に逆算（km/h スケール）
- 適用対象は `agePlayer` が動かす全キー（common/batting/pitching/fielding/baserunning/pitches）＝**加齢と完全に同じ集合**
- **乱数を一切消費しない**（純関数・決定論）

### B. 生存バイアス `survivorBonus(age, cfg)`（新規）

現実の支配下ロスターは「弱い個体が淘汰された後」の姿。34歳で支配下に残っているのは
**ポテンシャルが高かった個体だけ**。生成時にこれを模す（1年目リーグに生存バイアスの結果を織り込む）。

```
survivorBonus(age) = max(0, age - survivorFromAge) * survivorSlope   // ポテンシャルへの加点
```
- ポテンシャル生成の base に加える（maturity の前）
- これが無いと「37歳＝衰えただけの弱い選手」ばかりになり、ベテランが全員二軍に沈む（＝別の非現実）

### C. 年齢分布 `AGE_WEIGHTS`（config化）

現行 `18 + rng.int(20)`（一様18-37）＋ `drawYoungAge(skew 2.0)`（18に集中）を廃し、
**NPB実態に寄せた重み付き分布**から引く。18-19は高卒ドラフト、22-23は大卒/社会人の流入で膨らむ山型。

- `roster.ageWeights`: age → 相対重み（合計を70人へ写像）
- コア/デプスの区別（`corePitchers`/`coreFielders` の年齢帯分岐）は**廃止**
  （分布そのものが「若手厚め」を表現するため二重の細工が不要になる）
- 育成（farm）は別の重み `roster.devAgeWeights`（18-24中心・支配下より若い）
- ドラフト新人（`rookieAgeMin..Max` 18-22）はそのまま。**maturity 適用で自動的に「弱い新人」になる**

### D. 中心化 `baseLift`（較正の門番）

年齢構造の導入で一軍登録29人の平均能力が下がる（プロトタイプ実測: overall 54.5 → 52.7）。
**ポテンシャル生成の base に一律 `+baseLift` を足して、一軍29人の能力分布を現行と一致させる**。
これが「較正53指標を守る」ための唯一のノブ（プロトタイプでは baseLift ≈ +2 で mean 54.5 に復帰）。

### E. aging の grow/decline を本来の幅へ（config.tuning.aging.profiles）

生成側が「未成熟」を作るようになるので、加齢側は**本来の成長幅**に戻す。
- 現行の潰された値（power/ev grow 0.2）→ 18歳が peak まで9年で +10〜13pt 伸びる幅へ
- **多年インフレ（§11.3 Bug1）の再発防止が最大のリスク**。ただし今回は構造が違う:
  生成分布＝定常分布になる（生成と加齢が同一カーブ）ため、母集団は原理的に定常のはず。
  → `test/game_multiyear.test.mjs`（20年×得点環境の帯・単調非増加）が門番。**必ず通すこと**

### F. 1年目の一軍/二軍入替を有効化

`src/game/index.mjs:150` の `enableMoves: state.yearIndex > 0` → **常に true**。
- **較正53指標は非干渉**（`tools/calibrate.mjs` は `simulateSeason`（sim層・farm無し）で測るため）
- ただし `test/game_multiyear.test.mjs:123`「1年目は single simulateSeason と一致」が落ちる。
  このテストの主旨は「**加齢の混入が無いこと**」なので、**加齢非適用を直接検証する形に書き換える**
  （ゲーム層1年目 ≠ sim層 になるのは、二軍を持つゲーム層が入替を行う正しい帰結）
- 併せて `tools/calibrate.mjs` の二軍サニティに「ゲーム層1年目でもリーグ集計が帯内」を確認する行を追加

## 5.5 実装で判明した追加の欠陥（仕様策定時には見えていなかったもの）

実装して多年シムを回して初めて見えた、**年齢構造と不可分な2つの欠陥**。どちらも修正済み。

### (a) 引退の `minAge: 32` — 新陳代謝が NPB の 1/4 しか起きない
「32歳未満は絶対に引退しない」ため支配下の淘汰が起きず、多年でロスターが高齢化し続けていた
（実測: 支配下平均年齢が 26.7→**29.5歳**へ漂流）。NPB は毎年70人中8-12人が入れ替わる。
→ `minAge: 24`・`rampAge: 31`・`agePerYear: 0.075` へ。ただし maturity 導入で若手の**現在能力**は
構造的に低いため、能力ベースの引退判定は将来のエースを「能力40の使えない選手」として切ってしまう。
→ **`youthCreditPerYear: 0.9`**（peakAge までの残り年数 × これ を総合力に加算してから引退圧を測る）
を導入。TINSTAAPP は「伸びなかった中堅(25-28)が淘汰される」形で出る＝現実の戦力外通告の姿。

### (b) ドラフト選抜の上澄み — 多年で能力が単調インフレ
球団は surplus 付きプールから「自評価の最良」を指名するため、**指名された新人のポテンシャルは
プール平均より構造的に高い**。補正しないと毎年リーグへ「平均より強い個体」が注入され続け、
生存バイアス（弱個体の引退）と合わせて正の圧力になる（実測: 無補正だと15年で一軍EV **+1.5pt** →
SLG .402→**.433**）。decline を強めても止まらなかった（引退で高齢者が消えるので decline が効く前に
選手が抜ける）。
→ **`market.rookiePotentialLift: -2.5`** で相殺。一軍EV 55.3→55.2・平均年齢 27.2 で定常化。

## 5.6 較正の実務メモ（次に触る人向け）

年齢構造を入れると **K% と Contact% が同方向に動く**（どちらも「打者のコンタクト能力 vs 投手の空振り
能力」の別の現れ）ため、投手の強さ（`pitchStuff.grow`）だけでは両方を帯内に入れられない。
独立に動かせるノブは2つだけ:
- **`borderCsBase`**（ボーダー帯の見逃しストライク判定）: 下げると**見逃し三振だけ**減る（K%↓）。
  Contact% は不変（スイングしていない球なので）。副作用は BB%↑
- **`whiffTwoStrikeW`**（2ストライクの当てにいくスイング）: 上げると**空振り三振だけ**減る（K%↓）。
  副作用は Contact%↑（2ストライクのコンタクトが増えるため）

この2つで K% を落としてから、`pitchStuff.grow` で Contact% を合わせるのが収束が速い。
